# Atlas VPN

建立日期：2026-09-29

## 项目与服务器

Atlas Automation Hub 是现有云服务器的实例名称，不是一个已有网站项目。本项目是该服务器上的独立 VPN 项目。

已核实当前主机为 `atlas-ewr`，本机公网出口与用户提供的实例截图一致，IP 地理信息返回美国。本项目仅使用这台 Atlas，不接入附件中的东京节点，也不新租服务器。

## 已确认需求

- 仅供本人使用，主要从台湾及其他海外地区连接。
- Netflix 美区内容实际可播放是硬性目标；美国 IP、网站可访问或隧道连接成功都不单独构成验收通过。
- 苹果设备使用 Shadowrocket；Windows 使用另一款兼容客户端。
- 按需手动开启，开启期间采用整机全局连接，不做按网站自动分流。
- 最小管理功能包括设备新增与停用、配置与二维码、最近连接时间、流量统计。
- 设备上的客户端负责连接开关；管理页不冒充设备端 VPN 开关。

## 技术起点

优先验证 WireGuard；Shadowrocket 支持该协议，Windows 候选客户端为 WireGuard 官方客户端。VLESS + REALITY 保留为另一个技术候选，不因附件使用它就默认部署。

固定 Atlas 出口时，切换隧道协议不等于改变出口 IP 的平台识别结果。Netflix 美区播放需要单独实测，当前没有播放成功证据。

## 实施顺序与验收

1. 核对现有主机网络、系统与云端端口规则，准备可恢复的独立部署。
2. 先建立最小连接并验证 Shadowrocket 与 Windows 客户端的实际连通性。
3. 检查 IPv4、IPv6 和 DNS 路径，确认预期互联网流量使用 Atlas 出口。
4. 测试前核对样本影片的当前地区可用性，选择非仅有全球授权内容的美区测试样本；同时核实账号套餐与播放画质条件。
5. 从用户实际设备与网络验证目标影片连续播放至少 10 分钟，没有地区或代理报错。画质尚未指定，先以 1080p 为初测目标，不据此宣称 4K 已通过。
6. 根据连接实测与用户连续播放成功反馈推进最小管理页，同时独立保留美区片库差异、全局路由和设备侧测试为最终验收项；不把管理页完成等同于 Netflix 美区要求完成。

## 当前状态

WireGuard 已部署为 `wg-quick@atlasvpn.service`，使用 UDP 51820；iPhone、Mac 和 Windows 的独立配置与二维码位于 `clients/`。已验证服务器内隔离客户端的加密握手、DNS、IPv4／IPv6 美国出口，以及凭据撤销和恢复。

已经实际停止并回退本项目，核对防火墙与转发参数恢复基线，再重新部署复测；当前保留运行状态。没有重启 SSH、Docker 或备份服务。

名为 iPhone 的配置已产生来自外部公网端点的有效握手与双向流量，确认外部 UDP 入口和这份客户端凭据可用；配置名不代表实际设备识别。用户截图确认 Mac 上的 Shadowrocket 已开启，但 Global Routing 显示 Config，尚待改为 Proxy。

用户已反馈《Scandal》测试可以连续播放 10 分钟、没有报错。该项记录为用户报告的播放通过；画质、关闭 VPN 前后片目差异及美区识别仍待核实。Mac 专用配置随后也出现了有效握手和流量。设备端全局路由及 DNS／IPv6、Windows 实际连接仍待验证。

最小管理页已部署在 VPN 内网 `http://10.77.0.1:8787`，支持添加、停用、启用、配置下载、二维码、最近握手与当前流量。管理页另需密码；登录信息保存在 `clients/管理页登录.txt`。网页仅监听 WireGuard 内网地址，不绑定公网地址。浏览器功能、认证边界、手机布局与管理页回退均已测试。详见[使用说明](使用说明.md)、`VERIFICATION.txt` 和 `evidence/ui/VERIFICATION.txt`。

管理页运行数据位于 `/var/lib/atlas-vpn-ui/`，这是设备增删状态的实际来源；旧版 `server/keys.json` 是最初三份配置的基线，不应覆盖运行状态。`scripts/deploy.sh` 会优先采用管理页的运行状态。`scripts/snapshot-ui.py` 可在管理员身份下生成私有仓库用的时点快照；本次部署已生成，后续网页修改不会自动推送 GitHub。原有备份定时器未改动。

本项目已建立 Git 基线；VPN 阶段保存在 `feature/wireguard`，管理页阶段保存在 `feature/management-ui`，尚未合并到 `main`，以区分阶段成果与完整需求验收。
